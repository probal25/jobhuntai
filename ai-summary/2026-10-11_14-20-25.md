# Project State Summary - 2026-10-11_14-20-25

## 🎯 Project Goal
Build an autonomous job application pipeline: LinkedIn Scraping (Europe/Relocation) $\rightarrow$ Local LLM Triage (Ollama/Llama 3) $\rightarrow$ Tailored LaTeX Resume PDF generation.

## 🛠️ Technical Stack
- **Backend:** Spring Boot 3.4.x, Java 17
- **AI:** Spring AI + Ollama (Local LLM)
- **PDF:** `pdflatex` via custom LaTeX template
- **Storage:** MySQL / Spring Data JPA
- **Scraping:** Jsoup

## 🚀 Current Progress & Fixes
- **Async Workflow:** Transitioned from synchronous to `@Async` to prevent UI freezes.
- **LaTeX Environment:** Resolved font crashes (`tcrm1095`) and missing packages (`enumitem`) on Apple Silicon (M5).
- **Markdown Hallucinations:** Implemented aggressive stripping of markdown fences (```latex) and conversational filler.
- **Triage Logic:** Adjusted threshold to 60% and loosened relocation requirements to increase hit rate.

## ⚠️ Remaining Issue: LaTeX List Formatting
Despite multiple attempts, the Local LLM consistently outputs lists as plain paragraphs with leading dashes (`–` or `-`) instead of the required LaTeX command `\resumeItem{...}`.

**Current State of the Fix:**
- Implemented a `Post-Processing Guard` in `ResumeAdapterAgent.java` that attempts to regex-replace leading dashes/bullets with `\resumeItem` and `\resumeItemTech`.
- The LLM continues to bypass these guards or use unexpected characters, resulting in PDFs without bullet points.

## 📋 Next Steps for New Session
1. **Debug LLM Output:** Capture the raw string returned by `chatModel.call` in `ResumeAdapterAgent` to see exactly which characters are being used for bullets.
2. **Alternative Formatting:** Consider changing the LaTeX template to a simpler list format if `\resumeItem` is too difficult for the local model to maintain.
3. **Prompt Engineering:** Try "Few-Shot" prompting by providing 3-5 exact examples of `Input -> Correct LaTeX Output` in the system prompt.
4. **Verification:** Run a test loop with a small set of jobs to verify the bullet points appear in the final PDF.
